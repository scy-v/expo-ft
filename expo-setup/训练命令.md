# EXPO-FT 在线训练与独立评估命令

前提：服务器和本地环境按[安装命令](安装命令.md)准备好，并具有成功示教数据、SFT 权重及对应归一化统计。以下使用插槽任务和 2500 步权重的配置。

**执行顺序：服务器转换数据 → 服务器启动训练 → 本地启动机器人端。** 服务器负责模型推理和更新，本地负责机器人执行、采集与键盘接管；无需 NUC。

## 一、服务器执行

### 1. 激活服务器环境

```bash
cd ~/expo-ft
source expo-setup/activate.sh
```

服务器使用仓库根目录 `.venv`，下面的数据转换和训练命令在同一终端执行。

### 2. 转换成功示教数据

将 LeRobot 数据转换为 EXPO-FT 训练读取的 HDF5 格式，随机抽取 10 条成功示教：

```bash
python scripts/convert_lerobot_to_expo_ft.py \
  --dataset-root /home/suchenyu/.cache/huggingface/lerobot/scylearning/insert_black_rack_into_blue_slot_20260916_v01 \
  --output-dir ./data/online_rl/success \
  --mapping expo-setup/support/lerobot-ur5e-insert.json \
  --num-episodes 10 --seed 0 \
  --assume-success
```

`--num-episodes 10` 指定数量，`--seed 0` 固定抽样结果，`--assume-success` 表示这些示教均成功。输出为 `data/online_rl/success/原episode编号/traj.hdf5`，抽样信息保存在 `conversion.json`。

同一份数据和抽样配置只需转换一次；已有相同结果时复用目录。转换脚本不覆盖已有输出，重新抽样需换输出目录，并同步下一步的 `--dataset_path` 和 `--num_data`。

### 3. 启动在线训练

同步／异步命令默认设置 `WANDB_MODE=online`，自动上传训练指标和配置。本机首次使用需在服务器根目录 `.venv` 激活后执行 `wandb login`；启动日志中的run链接即为本次指标页面。日志仍在本地 `logs/wandb` 留存。

指标按现有逻辑在episode结束时提交，再由W&B后台上传，因此网页不会逐action立即刷新。需要离线记录时，将下方命令的 `WANDB_MODE=online` 改为 `WANDB_MODE=offline`；启动脚本也接受同名环境变量覆盖。修改默认值只影响新启动的进程，不会改变正在运行的离线进程或自动补传历史离线记录。

使用 2500 步全参 SFT 权重及配套归一化初始化，在线采用 LoRA 更新，Pi05 学习率为 `2.5e-5`：

#### 3.1 同步训练

每局结束后更新3次，下一局等待更新完成。

```bash
WANDB_MODE=online XLA_PYTHON_CLIENT_PREALLOCATE=false CUDA_VISIBLE_DEVICES=0,1,2,3 python train_pi_robo.py \
  --config_task=configs/task/ur_insert.py \
  --config=configs/model/expo_ft_ur_config.py \
  --config.pi05_weight_loader_path=./checkpoints/sft/ur_insert/2500/params \
  --config.pi05_assets_dir=./checkpoints/sft/ur_insert/2500/assets \
  --config.pi05_asset_id=scylearning/insert_black_rack_into_blue_slot_20260916_v01 \
  --dataset_path=./data/online_rl/success \
  --num_data=10 --seed=42 --batch_size=64 --utd_ratio=20 --max_steps=100000 \
  --update_type=episode --num_updates=3 --offline_ratio=0 \
  --replan_steps=8 --delay=0 --fsdp_devices=1 \
  --client_host=0.0.0.0 --client_port=8102 \
  --project_name=expo_ft_ur \
  --output_dir=./checkpoints/online_rl \
  --run_name=run_001 \
  --checkpoint_model --checkpoint_buffer \
  --checkpoint_interval=4000
```

#### 3.2 异步训练

与同步入口二选一，同一机器人不要同时启动两者。物理GPU **0、1训练，2推理**；`CUDA_VISIBLE_DEVICES=2,0,1` 将物理2号卡映射为进程中的逻辑0号卡，作者异步入口固定使用第一张可见卡推理。全局batch64分到两张训练卡，每卡32。`XLA_PYTHON_CLIENT_MEM_FRACTION=0.90` 由JAX读取，将每卡显存分配额度设为90%；关闭预分配仍保留此额度限制。这套命令按三张独占的80GB卡配置。

```bash
WANDB_MODE=online XLA_PYTHON_CLIENT_PREALLOCATE=false XLA_PYTHON_CLIENT_MEM_FRACTION=0.90 CUDA_VISIBLE_DEVICES=2,0,1 python train_pi_robo_async.py \
  --config_task=configs/task/ur_insert.py \
  --config=configs/model/expo_ft_ur_config.py \
  --config.pi05_weight_loader_path=./checkpoints/sft/ur_insert/2500/params \
  --config.pi05_assets_dir=./checkpoints/sft/ur_insert/2500/assets \
  --config.pi05_asset_id=scylearning/insert_black_rack_into_blue_slot_20260916_v01 \
  --dataset_path=./data/online_rl/success \
  --num_data=10 --seed=42 --batch_size=64 --utd_ratio=20 --max_steps=100000 \
  --offline_ratio=0 --ep_timeout_secs=120 \
  --replan_steps=8 --delay=0 --fsdp_devices=1 \
  --client_host=0.0.0.0 --client_port=8102 \
  --project_name=expo_ft_ur \
  --output_dir=./checkpoints/online_rl \
  --run_name=async_run_001 \
  --checkpoint_model --checkpoint_buffer \
  --checkpoint_interval=4000
```

异步在episode结束时，buffer达到batch64即启动后台持续更新，不等待10局，也不使用同步的 `--update_type`／`--num_updates`。120秒没有episode结束会暂停更新，下一局结束后恢复。权重在更新完成后发布，rollout取最新版本；已生成chunk继续执行。该入口仅使训练与rollout并行，`--delay=0` 仍在chunk边界阻塞推理。可使用同参数启动脚本 [run_server_async.sh](../scripts/ur/run_server_async.sh)。


核心配置文件（点击跳转）：

| 修改内容 | 配置文件与参数 |
|---|---|
| 手动保存开关、episode 上限、机器人 IP、相机、夹爪、控制参数 | [UR 核心 YAML：insert.yaml](../configs/ur/insert.yaml)，`online.max_episode_chunks` 默认60 |
| 服务器预热、固定全参 SFT rollout 测试开关 | [rollout.yaml](../configs/ur/rollout.yaml)，`warmup: true`、`sft_only: false` |
| 服务器在线模型、初始化权重、预测长度 | [EXPO-FT UR 模型配置](../configs/model/expo_ft_ur_config.py) |
| 任务提示词、上层频率、UR YAML 路径 | [UR task 配置](../configs/task/ur_insert.py)，通过 `ur_config_path` 加载上述 YAML |

batch、UTD、每 episode 更新次数及执行长度 `--replan_steps` 在下述说明对应的服务器启动命令中修改。

核心配置：

- **数据与模型**：`--dataset_path` 指向转换结果，`--num_data=10` 读取 10 条示教；权重与归一化均来自 `checkpoints/sft/ur_insert/2500`。
- **训练与执行**：batch=64，UTD=20，步数上限及 replay 容量为 100000；模型预测 50 步、每次执行 8 步，上层动作频率 10 Hz。
- **同步运行环境**：`CUDA_VISIBLE_DEVICES=0,1,2,3` 使用四张 GPU；`fsdp_devices=1` 对应四卡数据并行，推理使用第一张可见 GPU，与同步训练共用。关闭 JAX 显存预分配，W&B 使用离线记录，无需登录。

在线 episode 上限在本地 [configs/ur/insert.yaml](../configs/ur/insert.yaml) 设置：

```yaml
online:
  max_episode_chunks: 60
```

按 RLinf-rltoken 的口径换算为 `max_episode_chunks × --replan_steps` 个实际执行动作。默认 60 × 8 = 480 步；人工接管动作也计数，推理等待、复位等待和未执行动作的轮询不计数。成功或人工结束可提前终止。修改 chunk 上限只改该 YAML；执行长度由 learner 通过通信下发，不需在本地重复设置。服务器与本地需使用支持此传参的同版代码。

固定保存间隔由服务器命令设置；本地 [insert.yaml](../configs/ur/insert.yaml) 控制是否允许额外的按键保存：

```yaml
online:
  manual_checkpoint: true
  max_episode_chunks: 60
```

- 固定 step 保存默认由 `--checkpoint_model --checkpoint_interval=4000` 启用：跨过 4000、8000、12000……后，在该 episode 结束时保存，以实际结束 step 命名。
- **默认 `manual_checkpoint: true`**：额外允许 rollout 中在本地实体键盘上 **0.5 秒内双击 `-`**，请求本局结束保存。按键不结束 episode、不标记成功或失败。手动保存不推迟下一次固定 step 保存；两者在同一局重合只保存一次。
- **`false`**：仅关闭本地双击减号请求，固定 step 保存仍有效。服务器终端 Enter 强制保存及正常训练结束保存保留；同 step 不重复保存。`--checkpoint_buffer` 独立控制数据保存。

同步入口在本局网络更新完成后保存；异步入口向 learner 请求，等当前更新完成后保存完整 learner 状态，因而保存时局间等待可能延长。异步 checkpoint 是保存时的最新 learner 权重，不保证等于整局 rollout 使用过的某一版策略。两端需同步代码；本地开关在启动时读取。评估 YAML 不使用此开关。

服务器在连接机器人前预热 rollout 推理，并按正式 batch／UTD／分片配置编译 learner 更新。推理动作丢弃；更新预热会编译初始化及前几次更新后的稳定类型／分片签名，只编译、不执行梯度更新、不改变参数、优化器或采样随机数，不计入 episode 或 replay。两项完成后才进入监听；同步训练在第11局结束后首次更新，异步按上述buffer条件启动。配置或数据形状变化仍可能触发新编译。

标准 EXPO 使用服务器 [rollout.yaml](../configs/ur/rollout.yaml) 的 `sft_only: false`。若要使用固定全参 SFT 验证在线 rollout 轨迹，改为：

```yaml
warmup: true
warmup_update: true
sft_only: true
```

随后仍按上述训练命令启动，使用新的 `--run_name`。此模式额外加载一份初始化路径指定的**全参 SFT Pi05**，rollout 不经过残差 actor 或 critic 选择，且始终使用固定权重；learner 的数据采集、原有更新和保存逻辑保留。额外模型占用推理 GPU 显存，保持 `--delay=0`；诊断设置写入该运行的 `rollout_config.json`。保存的模型是正在学习的 EXPO learner，不是固定 SFT。

本模式用于对照在线动作执行、网络和键盘接管，不能等同于完整 EXPO 的推理耗时或正式算法结果。恢复标准 EXPO rollout 时将 `sft_only` 改回 `false` 并重启服务器。两种模式均预测50步、每次执行8步，上层10Hz、底层100Hz；同步推理仍会产生 chunk 之间的等待。

服务器完成模型初始化和预热后监听 **8102**。保持终端运行，再启动本地客户端。

模型 checkpoint 保存在 `checkpoints/online_rl/<run_name>/checkpoints/`，运行配置为同一运行目录下的 `ur_run.json`；以上同步命令的运行名为 `run_001`，异步为 `async_run_001`。W&B 日志写入 `logs/wandb`。新实验更换 `--run_name`；恢复同一实验时保持原配置及运行名，在命令末尾追加 `--resume`。

### 可选：定位 rollout 停顿

在服务器 [rollout.yaml](../configs/ur/rollout.yaml) 和本地 [insert.yaml](../configs/ur/insert.yaml) 中分别设置：

```yaml
timing_diagnostics: true
```

默认 `true` 生成诊断文件；设为 `false` 可关闭。配置修改后重启对应进程才生效；按原训练命令启动即可。服务器写入 `checkpoints/online_rl/<run_name>/timing/server-*.jsonl`，本地写入 `logs/ur-online/timing/robot-*.jsonl`，与W&B／动作日志分开。

输入准备进一步记录逐字段数组转换、图像校验、每个transform，以及JAX打包调用和完成等待；`thread_cpu_ms` 表示当前线程实际CPU耗时，不能单凭它确定等待原因。

记录覆盖RPC、逐路相机、机器人状态与控制锁、100Hz forceMode、动作确认、模型推理、取batch、权重复制／发布，以及局末数据／模型保存和复位等待。每段记录开始／结束时间；两端RPC通过 `rpc_id` 对齐，不依赖两台机器时钟完全一致。等待Enter的reset时间属于人为等待，应与episode内停顿区分。

服务器汇总示例（本地文件可复制到服务器后一起传入）：

```bash
python scripts/diagnostics/summarize_timing.py   checkpoints/online_rl/async_run_001/timing/server-*.jsonl --slow-ms 500
```

诊断使用有界后台写入队列，超载会丢弃诊断事件并记录计数，不阻塞机器人等待磁盘。启用时在推理与权重复制的关键GPU边界等待计算完成以准确计时，因此会增加同步和记录开销；定位结束后改回false。嵌套耗时不能直接相加，begin没有对应end可能表示正在等待、退出或事件丢失。

## 二、本地机器人电脑执行

先核对本地 [configs/ur/insert.yaml](../configs/ur/insert.yaml) 中的机器人 IP、夹爪串口、相机序列号和复位位姿，然后启动客户端：

```bash
cd ~/expo-ft
source expo-setup/activate-client.sh
python -m client.run_client \
  --host=100.101.84.9 \
  --port=8102 \
  --config_task_path=configs/task/ur_insert.py
```

本地使用 `client/.venv`，连接服务器 **8102**，按服务器请求初始化 UR 和夹爪；无需复制模型权重或示教数据。`--host=100.101.84.9` 为服务器的 Tailscale 地址，两端须能通过 Tailscale 互通。

连接后按提示操作：**首次 Enter 确认自动复位，复位后再按 Enter 开始；后续每局结束 → Enter 启用键盘手动复位 → 运动键调整位置、l/o 关/开夹爪 → 右方向键 `→` 确认自动回初始位 → Enter 开始下一局。0.5秒内双击 Space 标记成功；运行中的 Enter 不终止 episode。** 手动复位不记录训练数据、不计 chunk，无超时自动回位；步长与频率在 [insert.yaml 的 online.reset_teleop](../configs/ur/insert.yaml) 配置，默认平移0.045、旋转0.075、10Hz，复位期间 `/` 不切换步长。 本地交互终端原地显示 chunk 额度与动作余量（例如 `Chunks 12/60 +3/8 actions`），只按实际执行动作增长，人工动作也计入；等待不计数。运行中支持实体键盘接管，完整按键见[键盘与复位](support/UR迁移与运行.md#键盘与复位)。

若客户端持续提示连接失败，检查服务器是否已进入监听，以及地址和 8102 端口是否可达。软件与设备预检见[安装命令](安装命令.md#3-不连接机器人的软件检查)；独立评估见[下方独立评估](#三独立评估)。

## 三、独立评估

评估使用独立入口 `client.ur.evaluate`，不更新模型。先退出在线训练的机器人客户端，再启动评估。以下两种模型选一种：

| 模型 | 独立评估 YAML |
|---|---|
| 全参 JAX SFT（默认 2500 步） | [insert_sft.yaml](../configs/ur/insert_sft.yaml) |
| 在线 RL 保存的完整 EXPO 模型 | [insert_expo.yaml](../configs/ur/insert_expo.yaml) |

训练使用的 [insert.yaml](../configs/ur/insert.yaml) 不参与评估。评估次数 `record.num_episodes`、单次秒数上限 `record.episode_timeout_sec`、模型路径及模型服务地址只在评估 YAML 中配置。两端使用同一种评估 YAML；本地核对机器人、相机和复位位姿，`policy.host` 指向服务器（默认 `100.101.84.9`）。

### 1. 服务器：加载模型

```bash
cd ~/expo-ft
bash scripts/ur/serve_eval.sh --config configs/ur/insert_sft.yaml
```

评估在线 RL 模型时，将 `--config` 改为 `configs/ur/insert_expo.yaml`。其中 `model.checkpoint_dir` 指向训练输出的 `checkpoints` 目录（自动选最新 step，也可指定数字 step 目录），`model.run_config` 指向同一次训练的 `ur_run.json`；默认对应 `run_001`。归一化和模型架构须与训练匹配。

脚本自动激活服务器 `.venv`，加载并预热后监听 **8000**；使用哪张 GPU 在 `policy.cuda_visible_devices` 设置。

### 2. 本地机器人电脑：执行评估

```bash
cd ~/expo-ft
bash scripts/ur/evaluate.sh --config configs/ur/insert_sft.yaml
```

评估在线 RL 模型时，同样改用 `configs/ur/insert_expo.yaml`。脚本自动激活 `client/.venv`；远程模式不需要本地权重。沿用 VLA-Precision 评估交互，按终端提示复位、确认开始、标记成功/失败及保存录像。结果与录像写入本地 `logs/ur-evaluation`。

同机部署可将 `policy.host` 改为 `127.0.0.1`，仍分别启动两个终端。若选择单进程评估，将 `policy.location` 改为 `local` 并仅启动评估入口；该环境需具有完整模型依赖和权重。
