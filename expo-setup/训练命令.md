# EXPO-FT 在线训练命令

前提：**已有 LeRobot 成功示教数据集、SFT checkpoint 和对应归一化统计，服务器与本地环境已安装。** 以下按服务器、本地分别列出执行步骤。命令使用配置好的数据路径、字段映射、任务配置和 2500 步权重；更换数据或权重时同步修改对应参数。

先启动服务器，再启动本地机器人端，两个终端保持运行。服务器使用根目录 `.venv`，本地使用 `client/.venv`，无需 NUC。

## 一、服务器执行

### 1. 激活服务器环境

在服务器的仓库根目录执行：

```bash
cd ~/expo-ft
source expo-setup/activate.sh
```

### 2. 将 LeRobot 数据转换为 EXPO-FT 格式

这里转换为 **EXPO-FT replay buffer 读取的 HDF5 格式**，保留 UR 的状态和动作语义。训练入口读取 HDF5，`--dataset_path` 应指向转换结果目录。每份数据及抽样配置转换一次；已有相同转换结果时复用该目录，重新抽样时使用新的输出目录。

```bash
python scripts/convert_lerobot_to_expo_ft.py \
  --dataset-root /home/suchenyu/.cache/huggingface/lerobot/scylearning/insert_black_rack_into_blue_slot_20260916_v01 \
  --output-dir ./data/online_rl/success \
  --mapping expo-setup/support/lerobot-ur5e-insert.json \
  --num-episodes 10 --seed 0 \
  --assume-success
```

默认从整个 LeRobot 数据集中随机、不重复抽取 10 个 episode，只转换这 10 个；不足 10 个时转换全部。`--num-episodes N` 修改数量，`--seed` 修改随机种子（默认 0，同一数据集和种子可复现）。`--assume-success` 表示导入的示教均成功。输出结构为 `输出目录/数字episode/traj.hdf5`，脚本不覆盖已有输出。抽样种子和原始 episode ID 记录在输出目录的 `conversion.json`，子目录保留原始 ID。只有显式传入 `--all-episodes` 才全量转换；它与 `--num-episodes`、`--episodes` 互斥。映射格式说明见[数据接入文档](support/在线RL实现核对.md#现有资产与数据转换)。

### 3. 启动在线训练

在同一个服务器终端继续执行。以下使用 2500 步全参 SFT 权重及配套归一化作为初始化，在线训练使用 EXPO 的 LoRA 配置：

```bash
WANDB_MODE=offline XLA_PYTHON_CLIENT_PREALLOCATE=false CUDA_VISIBLE_DEVICES=0 python train_pi_robo.py \
  --config_task=configs/task/ur_insert.py \
  --config=configs/model/expo_ft_ur_config.py \
  --config.pi05_weight_loader_path=./checkpoints/sft/ur_insert/2500/params \
  --config.pi05_assets_dir=./checkpoints/sft/ur_insert/2500/assets \
  --config.pi05_asset_id=scylearning/insert_black_rack_into_blue_slot_20260916_v01 \
  --dataset_path=./data/online_rl/success \
  --num_data=10 --seed=42 --batch_size=64 --utd_ratio=20 --max_steps=100000 \
  --update_type=episode --num_updates=3 --offline_ratio=0 \
  --replan_steps=8 --delay=0 --fsdp_devices=1 \
  --client_host=0.0.0.0 --client_port=8102 \
  --project_name=expo_ft_ur \
  --output_dir=./checkpoints/online_rl \
  --run_name=run_001 \
  --checkpoint_model --checkpoint_buffer \
  --checkpoint_interval=2000
```

`--num_data=10` 沿用作者默认，加载转换后的这 10 条随机示教。若转换了 N 条且希望全用，将它改为 N 或 `0`（加载转换目录中的全部示教）。模型配置使用当前 UR 输入/输出约定，默认以已有 SFT 权重初始化在线 LoRA 模型；模型结构和归一化需与实际数据对应。

服务器监听 TCP **8102**，等待本地连接。checkpoint 保存在 `checkpoints/online_rl/run_001/checkpoints/`，运行配置保存在同级 `ur_run.json`。恢复已有训练时，使用相同路径和运行名，在上述命令末尾追加 `--resume`。

`batch_size=64` 为训练 batch 大小，`utd_ratio=20` 为更新比例，训练 seed=42 与数据抽样 seed=0 相互独立。`max_steps=100000` 设置运行步数上限，同时用作 replay buffer 容量；调整时一并考虑内存需求。

命令前的环境变量各有明确用途：`CUDA_VISIBLE_DEVICES=0` 选择 GPU；`XLA_PYTHON_CLIENT_PREALLOCATE=false` 关闭 JAX 启动时的大块显存预占，但并不会减少模型实际所需显存；`WANDB_MODE=offline` 让 W&B 写本地日志，无需登录或连接外网。W&B 日志目录由激活脚本设置到仓库 `logs/wandb`，JAX 编译缓存设置到 `expo-setup/outputs/jax`，均位于数据盘。

同等配置也可用 `bash scripts/ur/run_server.sh` 启动。初次运行使用 `run_001`；已存在实验不要覆盖，明确续训才添加 `--resume`。

## 二、本地机器人电脑执行

在本地的仓库根目录执行。任务配置内容与服务器保持一致；其引用的硬件 YAML 使用本地设备的 IP、串口、相机及复位参数。

```bash
cd ~/expo-ft
source client/.venv/bin/activate

python -m client.run_client \
  --host=211.86.155.68 \
  --port=8102 \
  --config_task_path=configs/task/ur_insert.py
```

本地需要能连接服务器 `211.86.155.68:8102`。若两端通过 Tailscale 连接，可将 `--host` 改为 `100.101.84.9`。同机运行时将 `--host` 改为 `127.0.0.1`。本地不需要复制数据集或模型权重。

连接后按本地提示确认复位和开始。运行期间支持键盘接管；双击 Space 标记成功，双击 Enter 标记失败。按键说明见[键盘与复位](support/UR迁移与运行.md#键盘与复位)。

独立模型评估见[评估命令](评估命令.md)；实际验证状态单独记录在[测试进展](测试进展.md)。
