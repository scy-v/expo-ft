# UR 独立评估：服务器和本地分别执行什么

本页只运行模型评估，不更新模型。在线训练见[训练命令](训练命令.md)。先结束本地在线训练客户端，再启动评估，避免两个程序同时控制 UR。

默认分两端：服务器加载模型并监听 **8000**，本地连接模型服务、执行机器人动作并保存评估录像/结果。下面 A、B **只选一种**；每种都是先启动服务器，再启动本地。两边脚本分别自动激活根 `.venv` 和 `client/.venv`。

## A. 评估已有的全参 JAX SFT 权重

使用 `configs/ur/insert.yaml`。服务器配置使用 `checkpoints/sft/ur_insert/2500` 全参 SFT checkpoint，`model.kind: sft`、`model.architecture: full`。

**服务器终端：**

```bash
cd ~/expo-ft
UR_CONFIG=configs/ur/insert.yaml bash scripts/ur/serve_eval.sh
```

服务器会加载权重并完成一次前向预热，然后等待本地连接。GPU 编号在服务器 YAML 的 `policy.cuda_visible_devices` 中设置。

**本地机器人电脑：** 先将本地 `configs/ur/insert.yaml` 中 `policy.host` 改成 GPU 服务器 IP，保持 `policy.location: remote`、`policy.port: 8000`。核对同一文件里的机器人 IP、串口、相机和复位位姿，再执行：

```bash
cd ~/expo-ft
UR_CONFIG=configs/ur/insert.yaml bash scripts/ur/evaluate.sh
```

## B. 评估在线 RL 训练后的完整 EXPO 模型

使用 `configs/ur/insert_expo.yaml`。使用在线训练保存的 checkpoint。该入口恢复 Pi05、edit actor 和 critic 等完整在线模型。

服务器 YAML 默认对应训练命令的 `run_001`：

```yaml
model:
  kind: expo
  architecture: lora
  checkpoint_dir: ./checkpoints/online_rl/run_001/checkpoints
  run_config: ./checkpoints/online_rl/run_001/ur_run.json
```

这是现有 YAML 的字段摘录，不要用它覆盖整份文件。按实际训练输出修改这两处路径：通用训练命令对应 `./checkpoints/online_rl/<RUN_NAME>/checkpoints` 和 `./checkpoints/online_rl/<RUN_NAME>/ur_run.json`。`checkpoint_dir` 指向 checkpoints 目录时取最新保存的 step，也可指定里面的数字 step 目录。保留对应训练的归一化路径、模型架构、预测长度及执行长度；默认在线 LoRA 对应 `architecture: lora`。

**服务器终端：**

```bash
cd ~/expo-ft
UR_CONFIG=configs/ur/insert_expo.yaml bash scripts/ur/serve_eval.sh
```

**本地机器人电脑：** 将本地 `configs/ur/insert_expo.yaml` 中 `policy.host` 改成 GPU 服务器 IP，保持 `policy.location: remote`、`policy.port: 8000`；核对设备参数，模型模式和执行长度与服务器一致，再执行：

```bash
cd ~/expo-ft
UR_CONFIG=configs/ur/insert_expo.yaml bash scripts/ur/evaluate.sh
```

## 两种评估共同的操作与输出

本地按终端提示开始、标记成功/失败及选择录像；沿用 VLA-Precision 评估交互。这里不是在线训练的键盘接管流程。录像和结果写入本地 `logs/ur-evaluation`；远程模式下，本地不需要模型权重文件。

同机部署时 `policy.host: 127.0.0.1` 即可，仍可用上述两个终端。若要单进程评估，可设置 `policy.location: local`，只运行本地评估入口；此时本地必须有权重及[完整模型依赖](安装命令.md)，不属于默认部署。

## 可选：服务器先做不连接机器人的检查

```bash
cd ~/expo-ft
source expo-setup/activate.sh
python -m client.ur.evaluate --config configs/ur/insert.yaml --check
python -m client.ur.evaluate --config configs/ur/insert.yaml --check-model
```

`--check` 只检查配置、路径和归一化；`--check-model` 实际加载并执行模型前向，需要足够显存。检查 EXPO 模型时换成 `configs/ur/insert_expo.yaml`。

运行与验证记录见[测试进展](测试进展.md)。
