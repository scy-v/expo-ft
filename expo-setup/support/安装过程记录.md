## 数据盘存储

按用户要求使用 `/data/suchenyu/expo-ft/`（检查时 `/data` 可用约 14TiB）。安装因会话中断而停止，确认无 uv 进程后，将已下载缓存、托管 Python 和尚未安装完成的 `.venv` 移动到数据盘，仓库原路径保留软链接；随后继续 `uv sync --locked`，复用下载缓存。

以下相对路径在仓库与数据盘保持一致：`.venv`、`expo-setup/uv-cache`、`expo-setup/python`、`data`、`checkpoints`、`assets`、`logs`、`expo-setup/outputs`。`expo-setup/logs` 仅存轻量安装与验证报告，仍留在仓库本机目录。

新机器首次准备示例（只适用于原目录和目标均不存在；已有内容先停止写入、迁移并验证）：

```bash
cd ~/expo-ft
mkdir -p /data/suchenyu/expo-ft/expo-setup
for rel in .venv expo-setup/uv-cache expo-setup/python data checkpoints assets logs expo-setup/outputs; do
  mkdir -p "/data/suchenyu/expo-ft/$rel"
  ln -sT "/data/suchenyu/expo-ft/$rel" "$rel"
done
```

软链接被 Git 忽略；重新 clone 不会自动恢复这些目录。不要直接复制虚拟环境到另一台机器，应按锁文件重新安装。

`source expo-setup/activate.sh` 同时将 `HF_HOME`、`HF_LEROBOT_HOME`、`OPENPI_DATA_HOME` 和 `TORCH_HOME` 指向 `expo-setup/outputs/` 下的对应子目录（实际位于数据盘）。既有全局缓存不会自动搬入；所有训练终端先激活该脚本。
