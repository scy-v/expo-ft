# 双卡独立网络更新测速（2026-11-17）

## 条件与统计口径

- 物理GPU0／1，2×NVIDIA A800 80GB；服务器根目录 `.venv`，JAX/jaxlib 0.5.3，FSDP1（数据并行）。原仓库提交 `4e9f77ce7479c4e848ceea9189c89b2770283407`，OpenPI `46407a41183b037313a383ff679683f2773b766d`，另含本次未提交的诊断代码；源码快照／指纹归档在logs。
- 使用 `configs/model/expo_ft_ur_config.py`、2500步全参SFT初始化在线LoRA、真实转换10条示教。学习率及优化器与作者配置一致；critic ensemble10／min2、N8／edit samples8、预测50／执行8。正式训练配置仍是全局batch64、两张训练卡各32、UTD20，GPU2独立推理；本测试不运行推理卡、不连接机器人，不是正式训练实验。
- 每个分项独立进程，先调用5次预热（包括首次编译），随后20次计时；每次接收更新后的参数和RNG，检查指标有限、计时期间JIT缓存大小不变，并等待全部GPU输出完成。输入batch固定复用，数据来自现有示教；独立诊断replay容量4000。
- 计时包括该分项前向、反向、优化器／其附属目标更新及两卡通信。critic包含Pi05生成下一状态候选动作，因此不是只计小型Q网络。排除CPU采样、图像预处理／augmentation、上传、JIT编译、推理缓存复制、机器人、W&B及checkpoint；残差actor不包含单独的temperature更新。
- 诊断脚本用UTD1构造单次batch，但不改正式训练UTD20，也不执行20次critic的融合整轮。分项JIT与正式融合JIT不同，不能将分项乘加当作正式整轮实测时间。开启详细时间诊断的GPU同步不参与本测速。

所有项均使用90% JAX显存额度。batch64三项、batch128 edit actor关闭预分配；batch128 critic与Pi05开启预分配，数值统计均排除预热。

初次采用生产的 `PREALLOCATE=false` 时，batch128 critic在第一轮预热申请8.51GiB失败，Pi05第一轮通过、第二轮预热申请11.82GiB失败。仅将 `PREALLOCATE=true`，额度保持0.90，两项均通过5次预热和20次计时，说明这两次OOM与按需分配／碎片有关，不能简单断言计算本身必然超过80GB。生产配置没有因此修改；独立分项通过不代表batch128的完整UTD20异步训练已通过。

batch128 critic与Pi05的每卡活跃显存峰值分别为 64.03／67.08 GiB，额度约71.33GiB。以上结果未包含同卡rollout、完整UTD20预取／融合及权重发布开销。

## 可复测命令

先确认物理GPU0／1没有其他训练任务。按上面的分配设置选择 `PREALLOCATE` 值；每次只运行一个分项，命令只生成诊断结果，不启动在线训练。

```bash
cd ~/expo-ft
source expo-setup/activate.sh
CUDA_VISIBLE_DEVICES=0,1 XLA_PYTHON_CLIENT_MEM_FRACTION=0.90 \
XLA_PYTHON_CLIENT_PREALLOCATE=false \
python scripts/diagnostics/benchmark_two_gpu_components.py \
  --batch-size 64 --component critic --warmup 5 --repeats 20 \
  --output /tmp/expo-bench-64-critic.json
```

`--component` 可选 `critic`、`edit_actor`、`pi05`；`--batch-size` 可选64、128。复测表中采用预分配的项，将上面环境参数 `XLA_PYTHON_CLIENT_PREALLOCATE` 改为 `true`。失败日志不纳入统计。
