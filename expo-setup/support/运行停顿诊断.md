## 异步终端更新状态

服务器step进度条每0.5秒原地刷新附加状态，例如 `net_updates=12, learner=updating, update_s=23.5, last_s=57.2`。分别为本次进程完成12轮更新、当前正在更新、本轮已用23.5秒、上轮耗时57.2秒。每轮为一次完整learner.update（当前UTD20含20次critic及后续Pi05／edit actor等更新），不是单个critic子更新；计数与当前进程的W&B `training/num_updates` 一致。

计时包括网络更新、推理缓存更新和发布，不包括取batch；取数据时显示 `preparing_batch`，尚未满足buffer条件为 `waiting_buffer`，超过episode等待阈值为 `paused`。无正在更新时update_s显示短横线。显示线程不调用JAX、不等待训练锁／机器人；rollout等待复位时仍刷新。沿用 `--tqdm` 开关，服务器重启后生效。3项CPU测试通过，尚未在真实训练中验证显示。

## 新增诊断

服务器 `configs/ur/rollout.yaml` 与本地 `configs/ur/insert.yaml` 均默认 `timing_diagnostics: true`（按用户测试要求开启）。两端使用更新后的配置重启后，写独立JSONL，不向W&B塞入大量细粒度事件；[启用流程](../训练命令.md#可选定位-rollout-停顿)。

| 事件前缀 | 用于定位 |
|---|---|
| `loop.*` / `inference.*` | step、观测、plan、Pi05输入处理／GPU执行／输出、critic编码与残差选择、device_get |
| `learner.network_update` / `learner.copy_inference_weights` | GPU更新完成与跨卡推理权重复制分别计时 |
| `learner.*lock*` / `rollout.take_published_weights` | buffer锁、权重发布和接收 |
| `learner.next_batch_and_upload` | 采样、预处理及设备上传提交 |
| `rpc.*` | 打包、发送、等待响应、解包；rpc_id匹配两端 |
| `camera.*` | 逐路相机read、图像resize和状态转换 |
| `robot.*` / `controller.*` | 位姿／速度／力／夹爪读取、I/O锁、动作确认、100Hz forceMode调用 |
| `episode.*` | replay插入、磁盘／W&B／checkpoint、复位及人工确认等待 |

开始／结束事件包含主机单调时钟、墙钟、进程／线程及可用的step/update/rpc_id。锁和读操作的组合span进一步慢时，可按内部子事件区分；100Hz控制线程不天然具有主线程的rpc_id。两台机器的单调时钟不可直接相减，跨机通过rpc_id匹配。

后台有界队列满时丢弃诊断事件并累计计数，避免控制线程等待磁盘；写盘失败记录错误并继续原流程。开启诊断会在GPU更新、推理和权重复制边界显式等待，避免把异步任务提交误当成任务执行完成。此同步会扰动调度，因此用于定位，不作为无诊断的性能基准。关闭时不增加GPU同步、不修改模型／奖励／数据／控制频率或保存触发规则。

## 输入准备细分计时

为继续定位step564／835，服务器输入准备增加逐字段 `numpy_asarray`、`image_uint8`、`image_validate`，以及 `data_transforms`／`model_transforms` 的逐级序号和实际类名。归一化、图像resize、分词等具体transform分别记录，不改变执行顺序；不记录图像、状态或文本内容。

`transforms_ready` 等待上游异步结果，`pack_dispatch` 记录JAX打包函数调用返回的耗时（可能包含上传／编译／调度等待），`pack_ready` 记录提交后的完成等待。后两者合起来才能反映打包端到端时间，不能把dispatch时间直接视作纯GPU计算。仅启用诊断时增加就绪等待，关闭时保留原pipeline调用及异步行为。

所有结束事件增加 `thread_cpu_ms`：它与duration_ms的差值包含线程未运行／等待的时间，不足以单独证明GIL、GPU或某把锁阻塞。8项CPU测试通过，覆盖嵌套transform顺序／结果、真实输入包装函数、开关对应GPU等待次数及日志配对；未启动新训练或验证真实GPU停顿。服务器重启后生效，原来运行中的进程不会自动加载新代码。测试日志：[input timing](logs/input-timing-cpu-20261117.log)。
