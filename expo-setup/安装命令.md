# EXPO-FT 安装命令

## 服务器（Learner）

大型目录位于 `/data/suchenyu/expo-ft/`，仓库原路径通过软链接访问，具体映射见[安装过程记录](support/安装过程记录.md)。新机器先准备独立数据盘目录及软链接再安装；不要直接覆盖已有文件夹。

所有命令在 `~/expo-ft` 执行；采用根目录 `pyproject.toml` 与 `uv.lock`，不使用 RECAP 环境。

```bash
cd ~/expo-ft
uv --version
# 仅首次、目录不存在时克隆；已有 checkout 不要覆盖。
git clone --branch expo_ft --single-branch https://github.com/pd-perry/openpi.git expo_ft/agents/vla/openpi
# 固定 OpenPI 版本（新克隆后执行）。
git -C expo_ft/agents/vla/openpi checkout 46407a41183b037313a383ff679683f2773b766d
export UV_CACHE_DIR="$PWD/expo-setup/uv-cache"
export UV_PYTHON_INSTALL_DIR="$PWD/expo-setup/python"
uv sync --locked
source expo-setup/activate.sh
uv pip check --python .venv/bin/python
XLA_PYTHON_CLIENT_PREALLOCATE=false python expo-setup/support/verify.py
```

机器未安装 `uv` 时按上游 README 安装：`curl -LsSf https://astral.sh/uv/install.sh | sh`。Python 使用 3.11，OpenPI 依赖包含 JAX CUDA 12 与 Torch；系统 NVIDIA 驱动单独验证，不根据 `nvidia-smi` 的 CUDA 显示值改写锁文件。

根项目只需要 OpenPI 与其 `openpi-client`，服务器不需要克隆 DROID 或安装 ZED / Spacemouse。安装后用下列命令激活，运行训练脚本前仍需切到仓库根目录：

```bash
cd ~/expo-ft
source expo-setup/activate.sh
nvidia-smi
```

真实安装状态、具体版本和验证范围见 [安装状态](support/安装状态.md)。

## DROID 本地机器人端（Actor）

此处“本地”指连接机器人设备的工作站，不指当前 GPU 服务器。保持两端 EXPO-FT 源码、OpenPI 提交和任务配置一致；不复制服务器的 `.venv`。

```bash
cd ~/expo-ft
# 两个目录不存在时执行；OpenPI 提交与服务器安装状态对齐。
git clone --branch expo_ft --single-branch https://github.com/pd-perry/openpi.git expo_ft/agents/vla/openpi
git clone https://github.com/pd-perry/droid.git client/droid
cd client
uv sync --locked
cd ..
source client/.venv/bin/activate
# 仅使用 ZED 相机时，在系统 ZED SDK 安装完成后执行：
bash client/install_pyzed.sh
```

ZED SDK、Spacemouse HID/udev 和 DROID 硬件标定按仓库 README 配置；`pyzed` 单独安装以适配客户端 numpy 约束。客户端依赖维护在 `client/pyproject.toml`，不要混装 server 环境。

## DROID NUC（机器人控制主机）

按 DROID 硬件文档部署 DROID/Polymetis；不能仅凭当前 Python 锁文件代替硬件主机配置。补齐机器人 IP、序列号、类型及标定后，从 NUC 的 DROID 根目录启动：

```bash
python scripts/server/run_server.py
```

UR 部署使用下节安装流程，无需 NUC。


## UR 本地机器人端（Actor，独立 client/.venv，无 NUC）

在连接 UR、DH 夹爪与 RealSense 的 Ubuntu x86_64 电脑执行。服务器继续使用根目录 `.venv`；本地远程训练/评估不需要 JAX、Torch、DROID、ZED、模型权重或示教数据。以下命令均在 `~/expo-ft` 执行。

### 1. 准备存储与固定版本源码

大型环境、下载缓存和运行输出放到 `/data/suchenyu/expo-ft/`。执行用户须有该目录写权限。已有路径必须指向相同目录；若是其他目录或已有独立环境，先确认无进程写入，再按仓库迁移规则处理，不覆盖。以下分支仅为不存在的路径创建软链接。

```bash
cd ~/expo-ft
uv --version
mkdir -p /data/suchenyu/expo-ft/client /data/suchenyu/expo-ft/uv-cache \
  /data/suchenyu/expo-ft/python /data/suchenyu/expo-ft/logs

if [ ! -e client/.venv ] && [ ! -L client/.venv ]; then
  ln -s /data/suchenyu/expo-ft/client/.venv client/.venv
fi
if [ ! -e expo-setup/uv-cache ] && [ ! -L expo-setup/uv-cache ]; then
  ln -s /data/suchenyu/expo-ft/uv-cache expo-setup/uv-cache
fi
if [ ! -e expo-setup/python ] && [ ! -L expo-setup/python ]; then
  ln -s /data/suchenyu/expo-ft/python expo-setup/python
fi
if [ ! -e logs ] && [ ! -L logs ]; then
  ln -s /data/suchenyu/expo-ft/logs logs
fi
readlink -f client/.venv expo-setup/uv-cache expo-setup/python logs

# 目录不存在时克隆；已有 checkout 应先核对提交，不覆盖本地修改。
if [ ! -d expo_ft/agents/vla/openpi ]; then
  git clone --branch expo_ft --single-branch https://github.com/pd-perry/openpi.git expo_ft/agents/vla/openpi
  git -C expo_ft/agents/vla/openpi checkout 46407a41183b037313a383ff679683f2773b766d
fi
test "$(git -C expo_ft/agents/vla/openpi rev-parse HEAD)" = 46407a41183b037313a383ff679683f2773b766d
```

`readlink -f` 应输出上述四个数据盘路径。`client/.venv` 在创建环境前可以是悬空软链接，因此下一步通过数据盘真实路径创建环境。

### 2. 安装锁定的 UR 依赖

只在专用 UR actor 环境中执行 `uv pip sync`，该命令会移除清单以外的包。复用环境时确认 Python 为 3.11；其他用途的环境应保持独立。

```bash
cd ~/expo-ft
export UV_CACHE_DIR="$PWD/expo-setup/uv-cache"
export UV_PYTHON_INSTALL_DIR="$PWD/expo-setup/python"
if [ ! -x client/.venv/bin/python ]; then
  uv venv --python 3.11 /data/suchenyu/expo-ft/client/.venv
fi
client/.venv/bin/python -c 'import sys; assert sys.version_info[:2] == (3, 11), sys.version'
uv pip sync --python client/.venv/bin/python client/requirements-ur.lock
source expo-setup/activate-client.sh
uv pip check --python client/.venv/bin/python
```

`client/requirements-ur.txt` 维护直接依赖，`client/requirements-ur.lock` 固定 Python 3.11/Linux x86_64 的完整版本，并从固定 OpenPI checkout editable 安装轻量 `openpi-client`。共有依赖沿用根锁文件，根锁文件没有的包参考 DROID client 锁文件；UR 专属 SDK 独立锁定。不要在 UR 环境运行要求 DROID 源码的 `cd client && uv sync`。日常使用 `source expo-setup/activate-client.sh`；它只激活 actor 并将 uv/Matplotlib 缓存指向本仓库存储路径。

### 3. 不连接机器人的软件检查

```bash
cd ~/expo-ft
source expo-setup/activate-client.sh
python -m client.ur.check --output expo-setup/support/logs/local-imports.json
python -m client.ur.check --config configs/ur/insert_expo.yaml
python -m client.run_client --help
python -m client.ur.evaluate --help
python -m unittest discover -s tests -p test_ur_integration.py -v
timeout 45s python -m unittest discover -s tests -p test_ur_protocol.py -v
timeout 45s python -m unittest discover -s tests -p test_ur_actor.py -v
```

预检默认只验证导入、标准 UR 配置和任务入口，不检查服务器权重文件。JSON 记录源码提交、解释器、包版本、检查范围和逐项结果；任一检查失败退出 1。协议测试使用 localhost 临时端口与假硬件，需要允许本机 socket；MP4 测试只在临时目录写合成图像。`test_ur_learner.py` 和 `test_ur_checkpoint.py` 属于服务器根 `.venv`，不加入本地测试命令。

### 4. 设备检查与相机采集

先核对 训练配置 `configs/ur/insert.yaml` 与所用评估配置（`configs/ur/insert_sft.yaml` 或 `configs/ur/insert_expo.yaml`） 中 UR IP、夹爪端口、两路相机序列号、复位位姿及负载。实体键盘需要 `/dev/input/event*` 读取权限，夹爪需要串口读写权限。使用桌面主机会话运行设备检查；受限沙箱的 USB/设备不可见不等于主机缺少驱动。

```bash
cd ~/expo-ft
source expo-setup/activate-client.sh
python -m client.ur.check --devices --output expo-setup/support/logs/local-devices.json
# 仅在相机未被其他采集程序占用时读取每台相机的一帧 RGB。
python -m client.ur.check --devices --camera-frames \
  --output expo-setup/support/logs/local-camera-frames.json
```

`--devices` 枚举相机和键盘能力、检查串口路径和权限，不读取按键、不打开夹爪、不连接 UR；`--camera-frames` 额外按配置逐台启停 RGB 流并检查尺寸/类型，不能替代双路持续采集或真机验证。多个键盘时选择实际设备，本机配置对应的设备路径为：

```bash
export EXPO_KEYBOARD_DEVICE=/dev/input/by-id/usb-Logitech_USB_Receiver-if01-event-kbd
```

只有设备权限检查失败且缺少相应组时，由本地管理员添加运行用户，再退出桌面会话并重新登录，使新组生效：

```bash
sudo usermod -aG input,dialout suchenyu
```

不以 root 运行 actor，不将设备全局设为可写。相机无法枚举时先检查 USB 连接、占用和已有 RealSense udev 配置。具体安装版本和设备验证范围见[本地安装检查](support/本地安装检查.md)。

### 5. 可选单进程本地模型评估

默认远程评估不需要模型依赖。选择 `policy.location: local` 时，本地还须具备权重、归一化和可用模型计算环境；先按服务器源码要求准备 OpenPI checkout，再从根锁文件导出模型依赖安装到独立 `client/.venv`：

```bash
cd ~/expo-ft
source expo-setup/activate-client.sh
uv export --locked --no-dev --no-emit-project --format requirements-txt --output-file /tmp/expo-model-requirements.txt
uv pip install --python client/.venv/bin/python -r /tmp/expo-model-requirements.txt
uv pip check --python client/.venv/bin/python
```

此模式的额外模型依赖不包含在 UR actor 锁定清单中；再次 `uv pip sync client/requirements-ur.lock` 会回到纯远程 actor 环境。不要为本地评估升级服务器锁文件。
