# EXPO-FT 结果摘要

## 1. 在线网络更新耗时（2026-11-17）

### 测试条件

- **测试配置**：4 × A800 80GB，服务器根目录 `.venv`；2500步全参SFT权重初始化、在线LoRA、真实10条示教。全局 batch=64（每卡16）、UTD=20、每局 num_updates=3；诊断 replay 容量4000。源码版本与完整配置见下方记录。
- **计时口径**：独立GPU测试，不连接机器人。分项各自预热后计时一次更新并等待GPU完成；正式融合update先执行3次预热，再连续计时3次。复用已上传的真实batch，不含编译、数据采样／上传、通信、复位和checkpoint保存；不是正式训练收敛结果。

### 核心结果

| 测量对象 | 执行次数／范围 | 实测耗时（秒） |
|---|---|---:|
| Critic更新，含Pi05目标动作推理 | 1次，batch64 | 1.1977 |
| Pi05自身训练 | 1次，batch64 | 1.9373 |
| 残差actor更新 | 1次，batch64 | 0.0424 |
| 温度参数更新 | 1次 | 0.0406 |
| Critic连续更新，含阶段预处理 | 20次 | 27.4327 |
| 正式完整update | 第1次 | 29.4683 |
| 正式完整update | 第2次 | 29.7482 |
| 正式完整update | 第3次 | 29.7423 |
| 正式完整update | 上述3次均值 | 29.6529 |
| 每局全部网络更新 | 上述3次合计 | **88.9587** |

- **更新次数**：一次完整update包含20次critic、1次Pi05、1次残差actor及1次温度更新；每局3个update共60次critic、3次Pi05、3次残差actor及3次温度更新。
- **批量含义**：critic一次处理buffer中的64条样本，各下一状态均需经过Pi05，当前每条生成8个候选chunk；这些动作只用于目标计算，不执行64次机器人rollout。单条观测的推理耗时不能直接与batch64的完整critic更新耗时相比。
- **数据来源**：[配置、方法与验证边界](support/更新分项测速.md)、[原始日志](support/logs/update-components-20261117.log)、[机器可读结果](support/logs/update-components-20261117.json)。首次拆分诊断因额外保留中间图像OOM，修正后完成上述测量；失败记录保留在详细报告中，不计入有效耗时。

### 结论与采用方案

- **耗时结论**：当前配置主要计算开销在critic的20次循环，包含Pi05目标动作推理，并非仅小型critic的反向传播。分项与完整update的JIT边界不同，不能用单项乘法或加法替代完整实测；尚未拆分critic内部Pi05推理、Q计算与反向传播各自占比。
- **配置与边界**：保留batch64、UTD20、每局3次更新；本次纯更新累计约89秒，实际在线等待还包含未计时开销。本结果不代表异步训练速度、真机运行表现或收敛时间。

## 2. 两卡训练＋独立推理的异步可运行性（2026-11-17）

### 测试条件

- **配置与口径**：物理A800 80GB GPU0／1训练、GPU2推理；SFT2500／10条真实示教、batch64（每卡32）／UTD20／FSDP1，诊断replay容量4000。正式更新函数连续执行3次，与合成观测推理并行；更新计时排除编译、数据准备、RPC及保存，包含推理缓存构建。不是正式实验。

### 核心结果

| 项目 | 结果 |
|---|---|
| 默认75% JAX额度 | 第一次更新通过，第二次OOM |
| 90%额度连续3次更新 | 58.003／57.188／57.754秒 |
| 3次均值／合计 | 57.649／172.946秒 |
| 同期推理次数 | 189次，输出有限值 |
| 每张训练卡活跃显存峰值／额度 | 63.74／71.33GiB |
| 推理卡活跃显存峰值 | 22.65GiB |

- **证据**：[异步复核方法、失败和原始日志](support/异步启动复核.md)。此处未拆分critic／Pi05／残差actor，不能直接沿用四卡分项时间。

### 结论与采用方案

- **采用配置**：异步命令设置JAX显存比例0.90，保留GPU0／1训练、2推理及batch64／UTD20。连续更新短测通过，可进入真机联调；不等于完整模型保存、100000容量或长时间稳定性已验证。
- **运行口径**：异步没有每局固定3次更新；这里的3次仅是诊断数量。单次更新约58秒时rollout仍并行，不能据此推断每局等待58秒。

## 3. 双卡batch64／128独立更新耗时（2026-11-17）

### 测试条件

- **配置与口径**：2×A800 80GB、FSDP1、SFT2500初始化LoRA、10条真实示教，每项5次预热后测20次，等待GPU输出完成。独立计时包含分项前向／反向／优化器／通信，排除数据准备、编译与权重发布；critic包含Pi05目标推理，生产UTD20未改。

### 核心结果

| 单次更新均值（秒） | batch64（每卡32） | batch128（每卡64） |
|---|---:|---:|
| critic | 2.20587 | 4.34865 |
| edit actor | 0.04126 | 0.04530 |
| Pi05 actor | 3.36903 | 6.73955 |

- **显存分配**：batch128的critic／Pi05关闭预分配时预热OOM，保持90%额度、开启预分配后完成测量；其余项保持关闭。不同分项／融合JIT口径不能直接乘加当作完整更新实测。
- **证据**：[完整分位统计、失败和复测设置](support/双卡分项测速.md)、[中文统计表](support/logs/two-gpu-components-20261117.png)。不是正式实验，不连接机器人。

### 结论与采用方案

- **采用配置**：生产仍用两训练卡batch64／UTD20及原分配设置。batch128这里只验证独立分项，未验证完整异步UTD20运行，不据此直接切换生产batch。

## 4. 在线rollout秒级停顿的定位证据（2026-11-17）

### 测试条件

- **配置与范围**：真机trace定位后，独立运行真实SFT2500／10条示教、batch64／UTD20，GPU0／1训练、2推理；32帧缓存观测走正式推理路径，修复前后各3轮更新。排除预热，不连接机器人，诊断replay容量4000。

### 核心结果

| 指标 | 原批量等待 | 逐数组等待 |
|---|---:|---:|
| 并发推理次数 | 179 | 190 |
| 上传就绪等待最大/ms | 3353.382 | 0.923 |
| 完整推理最大/ms | 3920.941 | 263.961 |
| 网络更新均值/秒 | 58.153 | 58.148 |

- **定位证据**：大learner状态的批量等待触发大量CUDA stream／event／callback调用同时等待；独立进程上传与CPU心跳无相同秒级停顿。CPU预处理替换及显存预分配均未解决，逐数组等待后的三轮无秒级停顿。
- **证据**：[完整复现、Nsight和逐次结果](support/异步上传阻塞修复.md)。19项相关CPU回归通过；此前真机逐步定位记录保留在[诊断历史](support/运行停顿诊断.md)。

### 结论与采用方案

- **采用方案**：大状态树逐数组等待，更新完成后构建推理缓存；保持CPU打包、batch64／UTD20、原显存设置及默认诊断开关。终端显示压缩并适配宽度。需重启服务器，尚未覆盖修复后的真机长跑，不保证所有其他来源的停顿均已消除。

# Summary 更新规则

## 通用要求

- 按主题使用连续编号标题（1、2、3……），每个主题固定采用下列三个小标题；规则置于文末，新增主题时顺延编号。
- 让未读源码的人也能复查“测了什么、结果是什么、采用了什么方案”。保留关键条件与证据，不记录讨论过程、排查流水和操作教程。
- 正文统一使用 `- **简短标签**：内容`，指标使用表格；同类信息合并为一条，不拆成零散段落，不用嵌套列表。
- 三部分按内容决定长短，不凑条目、不重复指标；仅突出关键结果，历史改动写入测试进展，完整命令和逐次记录通过链接引用。

## 测试条件

- 通常合并为一条“配置与口径”；条件较多时分为“测试配置”和“计时口径”两条。只保留影响比较的硬件、模型/权重、关键参数、样本数和统计范围。

## 核心结果

- 指标与对照优先用表格，注明单位；误差、内存变化等必要补充紧跟表格，数据来源以单独一条放在本节末尾。
- 核心结果包含多类指标时，按结果类型增加编号三级标题，将统计口径、表格及解释归入对应类别；单一结果可直接列出，数据来源统一放在末尾。
- 区分实测、估算和未通过项，不把不同计时范围或不同配置的结果直接混比。

## 结论与采用方案

- 用一至三条写清结论、最终采用的设置及关键参数；没有方案选择的主题只写一条结论。
- 简要注明影响结论的重要未验证范围，不将合成数据或局部测试写成真机效果，也不将数值近似写成完全一致。
