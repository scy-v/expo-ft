## 命令文档写入规则

适用于 `安装命令.md`、`训练命令.md` 和 `评估命令.md`。这三份文档回答“按什么步骤执行”，应当在不同日期重复使用，不依赖某次会话的进度。

- 按执行机器和操作顺序组织，只写必要前提、完整命令、参数含义、输出位置、复用和恢复等条件分支。安装、训练、评估各自成篇。
- 保留已确定的数据路径、权重路径、任务配置和参数，优先直接写命令行参数，不用多余的 `export` 中转；通用流程不要求把有效路径改成占位符。说明更换哪些参数即可复用流程。
- 禁止写入运行状态或进度提示，包括“当前已完成，直接跳过”“今天还没运行”“GPU 现在只剩多少显存”“已通过多少测试”“等待资源后再做”。标题、正文和代码注释都遵守此规则。
- 条件分支必须依据可检查条件。例如写“已有相同转换结果时复用该目录”，不写“我们已经转好了，跳过”；写“选择满足运行需求的 GPU”，不写某次检查的显存数值。
- 参数选择的历史、修改原因、资源快照和验证结果按下表归档。命令页仅同步最终参数与使用方法，可以链接记录页，但不重复粘贴状态结论。
- 修改后核对参数与启动脚本一致、路径完整、命令语法正确；纯文档整理不改变程序行为，不为验证排版启动转换、训练或机器人。

| 内容 | 写入位置 |
|---|---|
| 可重复的安装、训练、评估步骤 | 对应命令文档 |
| 做了什么变更、哪些检查通过或失败、待办 | `测试进展.md`，按日期与四类标题记录 |
| 环境安装状态、资源快照、详细检查依据 | `support/安装状态.md` 或对应检查记录，注明检查日期 |
| 原始命令输出、日志和检查报告 | `support/logs/`，记录页链接引用 |
| 正式实验配置、结果及结论 | `实验总结.md`；跨实验结论写 `summary.md` |
